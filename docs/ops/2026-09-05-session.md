## skill description の切り詰めと指示の見直し（別セッション）

pvncher の記事「Rethinking skills and prompts for GPT-6 Astra」をきっかけに、
Codex が実際に注入する skill カタログ（`~/.codex/sessions/*.jsonl` の
`<skills_instructions>`）を取り出して計測した。78 skill・18.6k 字で、
すべての description が 157 字前後で末尾を切られていた。切られる側は
「いつ使うか」のトリガー句だったので、dotfiles 由来 18 本の description を
トリガー句先頭・165 字前後へ書き直した（`: ` を含む英語 description は
YAML として壊れるので排除）。再起動後は 18/18 が全文で載る。

Codex 側の重複は `[[skills.config]]` で `~/.agents/skills/terminal-browser`
の default flavor を無効化して解消（78→77 行）。この配列は system layer
（`/etc/codex/config.toml`）では効かず、`~/.codex/config.toml` にだけ効く
ことを実測した。最初は user file を手編集して絶対パスを書いたが、home が
`tyamahori` とは限らないという指摘で見直し、`scripts/link` が `~` 付きパス
（Codex 側で展開されることを実測）を冪等に追記する形に改めた。
run ごとに curated-remote plugin（codex-security 等 27 本）が載ったり
載らなかったりする揺れがあり、こちらは未調査。

OMP は最初 `ignoredSkills` に `orchestration` を追加したが、実体は
`npx skills add stablyai/orca -g` で入れた `~/.agents/skills/orchestration`
（Claude Code は `~/.claude/skills` の symlink 経由で参照）だったので、
`npx skills remove orchestration -g` で 3 CLI から一括で外し、`ignoredSkills`

`retired_global_skills` に追加。`ignoredSkills` は明示 `/skill:` も塞ぐので、
使っていないだけの plugin skill は残した。

Claude Code には Codex と別の予算がある。バイナリを読むと skill 一覧は
`contextWindow × 4 × skillListingBudgetFraction`（既定 0.01 = 8k 字）で、
超過分は末尾切りではなく優先度順に description を丸ごと落として名前だけに

だけだったので `claude/settings.json` に `skillListingBudgetFraction: 0.03`
を置き、`claude -p` で 53 本すべて description 付きになることを確認した。

## t_wada規範のhook化 + omp usage widget

### 完了した作業

1. **機械グローバルgit hook（コミットログのWhy強制）**
   - `git/global-hooks/dispatch` + `git/global-hooks/checks/commit-msg-why` を新設。
     `dotfiles/.gitconfig` の `core.hooksPath` で全リポジトリ・全agent CLI・手動コミットに適用。
   - 判定: 4行以上の変更でsubjectのみのメッセージを拒否。
     merge / cherry-pick / rebase / fixup! / squash! / amend! / 3行以下のdiffは免除。
     逃げ道は `git commit --no-verify`。
   - dispatchは自前チェック後に各リポジトリの `.git/hooks/<hook名>` へ委譲（pre-commit framework等を壊さない）。
     husky / lefthookのリポジトリはローカル `core.hooksPath` が勝つため本hook自体がスキップされる（許容）。
   - dotfiles自身のローカル `git/hooks/commit-msg` は同チェックへのsymlink。
   - スモークテスト済み（拒否・通過・免除・委譲・unborn HEAD）。shellcheck通過。

2. **レビュースキルへの知識の置き場所観点の追加**
   - `agents/skills/github-pr-review/SKILL.md`: 観点(手順5)に「知識の置き場所」を追加。
   - `agents/skills/copilot-preflight/references/preflight-patterns.md`: 「Knowledge placement」節を追加。
   - Why-not コメント・テスト名の What は意味判定のためhook化せず、レビュー時1パスに寄せる設計判断。

3. **omp: 両subscription poolの使用率をwidgetで常時表示（commit 3637e8a）**
   - `omp/extensions/anthropic-usage-guard.ts` に `latestUsageRows` / `buildUsageLine` / `updateWidget` を追加。
     editor直下（belowEditor）に `usage Claude 5h 15% (3h) · 7d 34% (47h) · 7d:fable 64% (47h) │ Codex wk 3% (5d)` 形式で常時表示。
   - 使用率 >=80% 赤・>=50% 黄、reset残り時間をdimで併記。Codexの `spark:*` 枠はノイズとして省略（guardの判定もprimaryのみ）。
   - 更新は既存のsession_start + 5分毎チェックに相乗り。widget失敗はguard本体に波及しない。
   - 実TUI起動で描画を確認済み。`docs/omp.md` に記載追加。
   - 経緯: status lineの `usage` segment（非公開）はアクティブproviderの枠しか出さないため、両pool同時表示はguard拡張に実装した。

## ローカルSonarQubeによる完了前チェック

AIエージェントが生成したコードを完了報告前に検査するため、ローカルSonarQubeのQuality Gateを追加した。
リポジトリ直下に`sonar-project.properties`がある場合だけ、通常の検証後に`sonar-quality-gate`を1回実行する。
対象外のリポジトリは明示的にskipする。

ServerはOrbStack上の`sonarqube:latest`で起動し、`sonarqube.local`へ自動ルーティングする。
host portは公開せず、OrbStackのLinux kernel値を使い、Composeで`nofile`と`nproc`を明示する。
データはDocker volumeへ保存する。
初回実行ではadminパスワードと`GLOBAL_ANALYSIS_TOKEN`を生成し、macOS Keychainへ保存する。
Cloudへコードは送らない。

`sonarqube-cli`と`sonar-scanner`は別製品である。
前者は開発者・AIエージェント向けの`sonar`コマンド、後者はServerへプロジェクト解析を投入するScannerであり、今回のQuality Gateには後者を使う。

Docker volumesとKeychain項目がない状態から起動し直し、`dotfiles`の解析とQuality Gateの`PASSED`まで確認した。
OrbStack専用Composeへの変更後も、`sonarqube.local`の名前解決、host port未公開、Elasticsearch要件の充足を確認した。
同じドメイン経由の再解析でもQuality Gateは`PASSED`だった。
運用手順の正本を`docs/sonarqube.md`へ置き、READMEはglobal管理とproject-local設定の境界およびガイドへの導線だけを残した。

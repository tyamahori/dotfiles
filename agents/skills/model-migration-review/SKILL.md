# model-migration-review

モデルを切り替えたとき、現在の公式資料とグローバル指示を「収集 → 照合 → 仕分け → 項目別承認 → 適用 → 実動確認 → 記録」の順で扱う。
変更を自動で正当化したり、指示文を自動更新したりしない。

## 目的

モデル固有の制約、設定、推奨が変わるたびに、グローバル設定と常設指示を鮮度のある一次情報に照らす。
モデル名だけを置き換える作業にせず、変更が必要なものだけを人間の判断で反映する。

## 起動方法

モデルピンの差分があるかは、dotfiles リポジトリで次を実行して確認する。

```bash
scripts/model-pins check
```

変更があれば post-commit hook と月曜の通知が知らせる。
通知を受けたとき、または手動でモデル切替後の指示を見直したいときに、この Skill を起動する。

各環境で tool 名が異なる場合は、Claude Code、Codex、OMP の同等手段に読み替える。

## 対象範囲

対象は `~/dotfiles` のグローバル設定だけである。
モデルピンの正本は次の三か所とする。

- `claude/settings.json` の `.model`
- `codex/config.toml` の `model` と `model_reasoning_effort`
- `omp/config.yml` の `modelRoles:`

照合時は、必要に応じて次も対象にする。

- `agents/global-instructions.md`
- `omp/APPEND_SYSTEM.md`
- `agents/skills/*/SKILL.md`
- `codex/rules/`

各プロジェクトの `AGENTS.md`、`CLAUDE.md`、ローカル設定は対象外である。

## 収集

最初に `scripts/model-pins check` の差分を読む。
差分がない手動レビューでは、現在のピンを `scripts/model-pins show` で記録する。

`references/sources.md` から関連する公式資料を選び、既知URLは利用可能な読取ツールで直接取得する。
独立したまとまった調査だけを委譲し、URL、取得日、要点、取得失敗を受け取る。
委譲のためだけに工程を増やさず、資料の本文全文や推測を収集結果に混ぜない。

取得できなかったソースは URL と失敗理由を今回の記録へ残す。
そのソースの内容を別の資料で補完したと推測しない。
収集の対象は、今回変わった提供元と設定値に関係する資料だけに絞る。
たとえば Claude のモデル名だけが変わったなら、Claude のモデル一覧、移行ガイド、Claude Code changelog を優先する。
モデルの挙動に関する提案が出た場合だけ、プロンプトの概要や reasoning の資料を追加で読む。


## 照合

収集した要点を、現在の設定と指示に対して grep で照合する。
該当した箇所はファイルと行を挙げ、次の三種類に仕分ける。

| 判定 | 扱い | 例 |
| --- | --- | --- |
| 機械的 | 公式資料で明示された互換性・名称の差分。承認後にそのまま直せる。 | 設定キーの廃止、ツール名変更 |
| 判断 | 文脈、運用、書き手の意図で採否を決める。 | 強調表現の量、reasoning effort の既定値の変更 |
| 計測待ち | 効果の主張を現時点で設定変更へ結びつけない。 | 「指示への追従が強くなった」、 「より少ないプロンプトで済む」 |

機械的でも、変更前に提案表へ載せる。
公式資料が推奨していても、現在の運用で有効か不明なら判断または計測待ちにする。


照合結果には、変更する場合だけでなく残す理由も含める。
たとえば、現在の `model_reasoning_effort` が公式の既定値と異なっても、明示的な運用理由が残っていれば判断として比較する。
既存の文面が新モデルでも有効だと資料が示す場合は、変更なしと記録する。

### 旧モデルの癖への回避策の棚卸し

前回の journal と根拠を再利用し、変更された設定・関連指示と削除候補を棚卸しする。
初回または前回の根拠が不明な範囲は調べるが、変更のない規範を毎回全件再調査しない。
削除を提案する規範は `git log -S` で追加時のコミット本文まで戻り、次のどれかに仕分ける。
実装・設定・一次資料が変わった根拠は再確認し、調査済み範囲と未確認範囲を記録する。

| 種別 | 例 | 扱い |
| --- | --- | --- |
| マシンの事実 | SSH agent が 1Password、Python は uv 経由、dotfiles が公開 | モデル更新で古くならない。残す |
| 実測ルール | `agents/measured-notes.md` に事故の記録がある規範 | 残す。削るなら再発を測る前提で扱う |
| 書き手の好み | 文体、出力の長さ、日本語の規範 | 残す |
| 旧モデルの癖への回避策 | 特定モデルの誤動作を止めるためだけに書いた禁止や手順、特定モデル・バージョン向けの workaround | 削除候補。癖が消えたかは資料ではなく計測で確かめる |

回避策の削除は提案表に `判断` として載せ、根拠欄に追加時のコミットと止めたかった挙動を書く。
承認後に削り、1 週間後の記録で `agent-usage-weekly` の該当指標と再発の有無を確認する。
再発したら該当規範を戻し、理由を journal に残す。
コミット本文に理由がなく種別を決められない規範は推測せず、`保留` として次回へ持ち越す。

## 提案と承認

変更前に候補を次の表で提示する。

| 候補 | 根拠 | 判定 | 着地先 | 変更 |
| --- | --- | --- | --- | --- |
| 名前 | 公式 URL と現在の箇所 | 機械的、判断、計測待ち、却下、保留 | パス | 差分の要点 |

候補ごとにユーザー承認を取る。
承認前に指示、Skill、設定、pin を変更しない。
計測待ちは、測る内容と次回に判定する条件を提案し、今回の適用対象から外す。
候補がなければ、読んだ資料と「変更提案なし」を報告して終了する。


## 適用

承認された候補だけを適用する。
同じ責務を持つ既存の規範や Skill がある場合は新設せず、その箇所を更新する。

`CLAUDE.md` 系の変更は `claude-md-improver` を使う。
Claude が作った変更は Codex 系の環境で cross review する。
設定や指示を更新しただけで、未承認のモデルピンを ack してはならない。

作らないものは、公式資料の自動スクレイプ差分監視、文面の自動書き換え、ベクトル索引である。


## 検証

承認済みの変更後、新しいセッションでこの Skill の発火条件と設定の読込みを確認する。
設定の値だけでなく、対象 CLI または OMP がその値を読む入口を一度通す。

レビュー完了を確認できたら、dotfiles リポジトリで次を実行する。

```bash
scripts/model-pins ack
```

`ack` はレビュー済みの現在値を基準にする操作であり、検証前には実行しない。
新しいセッションが必要でその場で確認できない場合は、未確認のまま ack せず、必要な再起動後の操作を記録する。

検証では、既存セッションのキャッシュや既定値ではなく、変更後に始めたセッションを使う。
Skill は起動語で表示または適用対象になること、設定は CLI または OMP の解決済み値が pin と一致することを確認する。
指示文の効果を 1 回の応答だけで測ったと主張しない。

`scripts/model-pins check` が差分なしで終了することも、ack 後の確認に使う。
レビュー中に pin がさらに変わった場合は、新しい差分を起点に収集と提案へ戻る。
対象外のプロジェクト設定に差分が見つかっても、このレビューでは編集しない。

## 記録

`journal.md` の先頭に、1 回のレビューを 1 エントリとして追記する。
日付、`from → to`、読んだソースと取得日、提案、採用と却下・保留、検証結果を残す。
取得に失敗したソースもここに残す。

モデルピン変更の 1 週間後、`agent-usage-weekly` の対応週の数値を同じエントリへ追記する。
比較で悪化が確認できた場合は、理由を記録して以前の設定または指示へ戻す。

記録の「1週間後」には、対象期間、比較した `agent-usage-weekly` の数値、変化の判断を書く。
数値が不足している、または比較条件が変わった場合は、効果不明として扱う。
悪化を確認したときは、元の pin に戻す前に、悪化した値と戻す対象を提案し、承認後に戻す。

journal は今回の判断の履歴であり、公式資料の本文やセッションログを転記する場所ではない。
新しいサイクルを上に追加し、後から追記する 1 週間後の結果も同じエントリに置く。

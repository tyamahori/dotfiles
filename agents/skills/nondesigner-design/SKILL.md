# nondesigner-design

Robin Williams『ノンデザイナーズ・デザインブック』の思想を、agent が HTML や資料の構成に当てられる点検項目と CSS の型に落としたもの。
`frontend-design` が配色・書体・レイアウトの初期案を決め、`ja-html-typography` が和文の改行を守る。この skill はその後、**ページ全体の構成が読み手の目をどう導くか**を監査して直す。

## この skill が答える依頼

これまで実際に出た依頼。同種の言い方が来たら、この skill を読んでから着手する。

- 「Claude Artifact に HTML の資料をアップした際のデザインがいけていない」
- 「改善はしたけど配置の問題は残る。横幅を伸ばすのか、折りたたんで改行して配置するのか」
- 「ノンデザイナーズデザインブックの内容を活用して資料の HTML の構成を見直せる？」
- 「関係者に説明できる資料にしたい」（読み手が非エンジニアで、構造が一目で伝わる必要がある）

## 思想

1. **名前を付ければ見えるようになる（ジョシュアツリーの法則）。** 監査は「なんとなく変」で終えず、4 原則のどれが破れているかを名指しする。報告も原則ごとに書く。
2. **目の動きを設計する。** 「最初に目が行くのはどこか、次はどこか」を自問し、その順番が読む順番と一致するように大きさ・位置・余白を決める。ページを見て 3 秒で「何が主役か」が言えなければ構成が失敗している。
3. **臆病になるな。** 中途半端な差は「ちょっと違う」だけで、意図が読めずかえって散らかる。差を付けるなら誰が見ても分かるほど付ける。付けないなら完全に同じにする。余白も同じで、狭い余白を全体に均一に振るより、大きく空けるところと詰めるところを作る。
4. **関係のあるものは近づけ、無いものは離す。** 余白は「余り」ではなく、関係を表す情報。物理的な距離が意味的な距離と一致していなければ、読み手は違う関係を読み取る。
5. **端をそろえる線を 1 本決める。** 中央揃えは弱い。ページ内の要素は見えない 1 本の線（多くは左端）に乗せ、何かを「ちょっとずらす」ことをしない。ずらすなら意図が分かるほどはっきり。
6. **書体はコンコード（同一）かコントラスト（明確に別）か。** 似て非なる組み合わせ（コンフリクト）が一番弱い。差を付ける軸は大きさ・太さ・構造（書体の系統）・形（大文字・小文字、正体・斜体）・方向・色の 6 つで、2 軸以上を同時に動かすと差が明確になる。

## 点検の順序と CSS の型

書籍の順（近接 → 整列 → 反復 → コントラスト）で見る。近接と整列が構成、反復とコントラストが統一感と階層を作る。各項目は「症状 → 直し方 → CSS の型」の順。

### 近接（Proximity）

症状:
- 節内の余白が全部同じ値（例: 14px 均一）。見出しと本文、かたまり同士、表と注記が同じ距離で、どこで話題が切れるか分からない
- 図の「流れの中の矢印の間隔」が「別の流れとの間隔」より広く、別の流れが 1 本につながって見える
- 目次や札が幅によって 1 項目だけ次の行に孤立する

直し方: 余白を 3 段以上のスケールにし、意味的な距離と対応させる。節間 > かたまり間 > 見出し→内容 > 表→注記。関連要素の内側の間隔は、外側の間隔より必ず小さくする。

```css
.body { display:grid; gap:clamp(48px,6vw,72px); }      /* 節間: 一番大きい */
section > * + * { margin-top:28px; }                    /* かたまり同士 */
section > h2 + * { margin-top:16px; }                   /* 見出し → 内容: 見出しは内容に寄せる */
section > .tbl + .note { margin-top:14px; }             /* 表 → 注記: 一番近い */
.pipes { gap:22px; }  .pipe { gap:6px; }                /* 流れの中 < 流れの間 */
nav ol { display:flex; flex-wrap:wrap; gap:6px 24px; }  /* 孤立を出さない: 固定列ではなく流す */
```

### 整列（Alignment）

症状:
- 見出しに番号用の固定列があり、見出しの文字が本文より右にずれている（h2 と p の左端が違う）
- 札（stamp）や補助ラベルが見出しの下に置かれ、大 → 小 → 中の順で目が迷う
- 並列の箱（フロー図のノード、カード）の幅がばらばらで、左右端が揃っていない
- 中央揃えと左揃えが混在

直し方: 左端を 1 本にする。番号や札は見出しの**上**に小さなキッカーとして置き、小 → 大 → 中（キッカー → 見出し → リード）の階層にする。並列要素は共通グリッドに載せる。

```css
h2 .n { display:block; margin-bottom:6px; }             /* 節番号はキッカー。見出し本文は左端に乗る */
.stamp { justify-self:start; }                          /* 札は h1 の上、左端 */
/* 並列の流れを同じ列に載せて箱の左右端を揃える。行ごとの入れ物は display:contents で透過 */
.pipes { display:grid; grid-template-columns:1fr 22px 1fr 22px 1fr; }
.pipe { display:contents; }
.pipe + .pipe > :first-child { grid-column:1; }
```

### 反復（Repetition）

症状:
- 同じ役割の要素（札・節番号・h3・表キャプション・表ヘッダ）が別々の書体・サイズ
- ある節だけ式が `<p><strong>` で、他の節は `<pre>`。ラベルが付いている節と付いていない節がある
- 表ごとに列見出しの書き方や数値の揃え方が違う

直し方: 役割ごとに**ラベル族**を 1 つ決め、同じ役割は必ず同じ型にする。節の骨格（例: 式 → 定数 → 計算例 → 注記）も全節で同じ順・同じラベルにする。

```css
/* ラベル族: 小さなモノスペース + 字間広め。役割が同じものは書体・サイズ・字間まで同一 */
.stamp, .n, h3, caption, thead th { font-family:var(--mono); font-size:.74rem; font-weight:500; letter-spacing:.08em; }
td.num, th.num { text-align:right; font-variant-numeric:tabular-nums; }   /* 数値列は全表で右揃え・等幅数字 */
```

### コントラスト（Contrast）

症状:
- h3 が本文よりわずかに小さい（16px に対して .95rem 600）。「ちょっと違う」だけで階層に見えない
- h2 とリード文の差が小さく、どちらが見出しか一瞬迷う
- 強調したい出力（結果・結論のノード）が枠線色だけの差
- 色が装飾で使われ、意味（負数・警告・結果）と結び付いていない

直し方: 階層が隣り合う要素は、大きさ比 1.25 以上か書体の系統を変える。両方変えれば確実。ラベルは本文より**小さく別書体**に落とし、見出しは本文より**大きく別書体**に上げる。結果には面色を入れる。色は意味にだけ使う。

```css
h1, h2 { font-family:var(--mincho); }                   /* 見出しは本文（sans）と系統を変える */
h2 { font-size:1.6rem; }  .lead { font-size:1.1rem; }   /* 1.6 / 1.1 / 1（本文）で 3 段 */
.node.out { border-color:var(--accent); background:var(--accent-soft); }   /* 結果は面で差を付ける */
.neg { color:var(--neg); }                              /* 色は意味にだけ */
```

### 構成（幅と折り返しの判断）

「横幅を伸ばすか、折り返すか」は CSS だけでは決まらない。次の閾値で決め、実行は CSS に任せる。

- 式・コードは**折り返さない**（`white-space:pre; overflow-x:auto`）。半幅の `.split` に押し込まず全幅に置く。途中改行は意味を壊すので、狭い幅では横スクロールが正しい
- 表は列数で決める: **6 列以下**は本文幅、**7〜8 列**は本文カラムを抜けて shell 全幅へ張り出す（`.breakout { grid-column:1/-1 }`）、**9 列以上か長文の説明列がある**なら説明列を表から外して行下の注記にするか、行を縦積み（カード）にする
- 2 列並べ（`.split`）は**本当に並列の対**だけ（例: 定数 | 職業係数）。式と定数のように主従があるものは縦に積む
- 表のセルは既定 `nowrap`、自由文の列だけ `white-space:normal; min-width:18em`。数値列が折れるのが一番読みにくい

## 手順

1. **現状を測る。** headless Chromium で 560 / 720 / 1200px に描画し、下の検証 JS で左端の集合・余白の段数・見出し比・横はみ出しを取る。目で見た印象ではなく数値で症状を確定する
2. **4 原則で名指しする。** 症状を近接・整列・反復・コントラスト・構成のどれかに分類する。分類できない違和感は放置せず、どの原則の観点かを考え直す
3. **型を当てる。** 上の CSS の型を既存の変数名・クラス名に合わせて入れる。新しいクラスを増やすより、既存の要素に役割クラスを付けて族にまとめる
4. **再計測して報告する。** 原則ごとに「症状 → 直し方 → 測った結果」の順で書く（例: 「箱の left が 320 / 594 / 868 の 3 値に収束」）。スクリーンショットは `<git toplevel>/.agent-msgs/screenshots/` に置く

## 検証

```js
// 各幅で実行。値が期待から外れた項目だけ直す
const lefts = [...document.querySelectorAll('h1,h2,section > p,section > .tbl,section > .panel')]
  .map(e => Math.round(e.getBoundingClientRect().left));
[...new Set(lefts)]        // 整列: 1 値（狭幅）〜 2 値（左ナビ付き wide で h1 の全幅と本文カラム）。3 値以上ならずれている
const gaps = [...document.querySelectorAll('section > * + *')]
  .map(e => parseFloat(getComputedStyle(e).marginTop));
new Set(gaps).size                                        // 近接: 3 以上（均一なら 1）
const fs = s => parseFloat(getComputedStyle(document.querySelector(s)).fontSize);
fs('h2') / fs('p') >= 1.25 && fs('p') / fs('h3') >= 1.25   // コントラスト: 隣り合う階層は 1.25 倍以上
new Set([...document.querySelectorAll('.stamp,.n,h3,caption,thead th')]
  .map(e => { const c = getComputedStyle(e); return c.fontFamily + c.fontSize + c.letterSpacing; })).size  // 反復: 1
document.documentElement.scrollWidth > innerWidth         // 構成: false
[...document.querySelectorAll('.formula')].map(p => p.scrollWidth > p.clientWidth)   // 720 以上で false
```

改行の検証（`.nowrap` の分断、先頭列の折返し、compatMode）は `ja-html-typography` の検証項目をそのまま使う。

## 範囲

- 対象は人が読む成果物すべて。HTML が主だが、スライド構成案や Markdown レポートの見出し階層・余白・並列性の判断にも同じ原則を使う（CSS の型は HTML のみ）
- `visual-html-renderer` と archify の出力は固定テンプレートなので触らない。見た目を直したいなら手書き経路へ切り替える
- 配色・書体の初期選択は `frontend-design`、和文の改行は `ja-html-typography`。この skill は両方を読んだ後の構成監査

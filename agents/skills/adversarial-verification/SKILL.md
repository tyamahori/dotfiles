# adversarial-verification

成果物を作った文脈から切り離した別の目に、**壊すつもりで**見させて品質を確かめる。
「レビューして」との違いは構えで、「課題がある」前提で反証を試み、改善案の羅列ではなく
**判定と根拠**を返す。AI の出力は常にもっともらしく本人は自分に甘いため、
別コンテキストの懐疑者に反証させる必要がある。

**採否を決めるのは常に人間。** 検証結果は指摘であって正解ではない。受ける／弱めて受ける／
却下するを人間が判断して初めて完了する。破壊的・外向きの操作を検証結果だけを根拠に実行しない。

## 成立要件（4つとも満たす）

1. **独立性** — 成果物を作った会話文脈を引き継がない fresh context に検証させる。
   Claude Code、Codex、OMP の fresh subagent、または別モデルの新規セッションがこれを満たす。
2. **反証の役割づけ** — 「レビューして」ではなく「反証を試みろ／壊しに行け」。
   成立していない箇所を探しにいく検討にする。
3. **接地（グラウンディング）** — 事実の主張（数値・仕様・外部事実）はモデルの記憶ではなく
   一次情報に当たらせる。Web 検索・原典・実データ。確認できなければ「未検証」と明記させ、
   推測で断定させない。ax（`~/.agents/skills/ax`）を使う。
4. **判断できる出力** — 指摘ごとに深刻度・根拠・確度を付け、人間が採否を決められる形にする
   （下記出力形式）。

## 出力形式

指摘ごとに必ず4項目:

- **指摘**: 何が成立しない可能性があるか（一言）
- **深刻度**: 高（結論が覆る）/ 中（修正が必要）/ 低（条件つきで成立）
- **根拠**: なぜそう言えるか。一次情報を確認したらその出典
- **確度**: 高 / 中 / 低（推測を含むなら低）

最後に **「反証を試みたが壊せなかった点」** を1〜2行（なければ「なし」）。これは
成果物の一番堅い部分を示すと同時に、全指摘が反証で埋まっていないかの過剰指摘センサーになる。

## 機構A: 現在のランタイムで fresh subagent を並列起動（既定）

fresh context の懐疑役を複数、**観点を分けて並列**に立てる。役割・観点はこちらで割り当てる。
2パスで回す — 過剰指摘（機構の失敗①）を第2パスで削るため。

### パス1: 反証（find）

懐疑役は一つの batch で並列起動し、親の会話履歴を渡さない。ランタイムごとの入口は次を使う。

- Claude Code: `Agent` の `general-purpose`
- Codex: `spawn_agent` を `fork_turns="none"` で起動
- OMP: `task` batch。読取専用の事実確認は `scout`、コードレビューは `reviewer`、その他は `task`

成果物の種類に合わせて、次の観点から3つ選ぶ。

- **事実・出典** — 数値・仕様・外部事実を一次情報で裏取りし、誤り／未検証を突く
- **論理・前提** — 前提の飛躍、一般化しすぎ、n=1、相関を因果と取り違え、結論の飛躍
- **目的適合・成立性** — 成果物が目的／読者／要件を満たすか、致命的な欠落はないか
- （コードなら上記に代えて／加えて）**反例・エッジケース** — 壊れる入力・境界・競合を具体的に構成

各懐疑役へのプロンプトは下記雛形。fresh context・反証役・接地・出力形式を必ず含める。

### パス2: 指摘の検証（verify）

パス1の指摘を集約・重複排除し、**指摘ごとに別の fresh エージェントで再検証**する
（「これは本当に欠陥か、レビュアーの言い過ぎか」）。判定は三値で返させる:

- **AGREE** — 指摘は成立している。残す
- **DISAGREE_EVIDENCE** — コード・一次情報上の証拠を示して反証できた。棄却する
- **DISAGREE_CONCERN** — 疑義はあるが反証の証拠までは無い。**棄却しない**。
  確度を下げて残し、人間の採否判断に回す

棄却できるのは DISAGREE_EVIDENCE だけ。証拠を示さない「なんとなく違う」での棄却は
機構の失敗③（曖昧棄却）。検証の重要主張には反証者を複数立ててよいが、票として
数えるのは証拠つき反証のみ — 証拠なしの頭数では指摘を落とさない。

第2パスは機構の失敗②（ろくに検証せず「合格」と返す手抜き）への対策も兼ねる:
根拠のない「問題なし」は受け付けず、パス1が挙げた各指摘に対する明示的な判定を要求する。

判定が割れた指摘（AGREE と DISAGREE_EVIDENCE の衝突など）に限り、双方の根拠を
突き合わせてもう1往復してよい。全指摘の反復はコストに見合わない — 割れたものだけに絞る。

規模が大きい・網羅性が要る監査でも、ランタイム固有の未共有 Workflow 名を前提にしない。
同じ find → 指摘ごとの並列 verify を、利用可能な subagent batch で構成する。

## 機構B: クロスモデル（Codex / Gemini）

検証側と成果物側が同一モデルだと盲点を共有する（モデルの知識自体の誤りがすり抜ける）。
回避策は接地の徹底（要件3）と、重要成果物では**別モデルに検証させる**こと。

運搬手順は `omp-herdr-collab` スキルが正本。使い分け:

- Herdr 内で検証役を Herdr agent として利用できる → 単発・往復とも
  `omp-herdr-collab`（coordinator は omp セッション）。
- Herdr 外 → skill 化された transport はない。GUI の別モデルセッション
  （Claude / Codex）に下記雛形と成果物を手動で貼る。

いずれもこのスキルの雛形・出力形式・成立要件をそのまま渡す。別ツールの新規セッションに
雛形を貼れば、それがクロスモデルの敵対的検証になる。

## 発火

- **明示** — `/adversarial-verification`、または「敵対的検証して／反証して／裏取りして」。
  成果物を作ったセッションでそのまま頼んでよい（検証は fresh の別コンテキストで走る）。
- **自動** — もっともらしい成果物（リサーチ結果・設計案・ADR・提案書・記事）を確定・提示
  する直前に、鵜呑みが危うい主張が含まれるならこのスキルを想起して検証にかける。
- **提案** — やり直しコストの高い成果物（公開前記事・意思決定文書・リリース前コード）を
  出したときは、実行前に「敵対的検証しますか」と一言提案する。コストが 3〜10 倍かかるため、
  常用はこの種の成果物に絞り、軽い成果物では提案にとどめる。

## 注意点

1. **健全な成果物にも指摘は出る。** ギャップを探せと指示された懐疑役は大抵何か報告する。
   全指摘を追うと過剰設計に行き着く。指摘が出た＝間違い、ではない（第2パスと「壊せなかった点」で緩和）。
2. **手抜き合格のほうが危険。** 検証者の最大の失敗は、ろくに検証せず「合格」と返すこと。
   敵対的検証の出力は普段以上に「それっぽい」ため「もう十分」と思いがち。「大丈夫」と
   言われても人間が自分で見る。
3. **曖昧な棄却も同じくらい危険。** 検証役が証拠を示さず「言い過ぎでは」で指摘を捨てると、
   反証役と検証役がなんとなく合意（false consensus）して本来残すべき指摘が消える。
   棄却は証拠つき反証に限る（パス2の三値判定で緩和）。
4. **コスト。** マルチエージェントは同等タスクの 3〜10 倍のトークンを消費する
   （Reviewer/Critic 往復型の実測で zero-shot 比 約4.5倍、精度は F1 +3pt）。やり直し
   コストの高い成果物に絞る。
5. **同一モデルは盲点を共有する。** 接地（要件3）と、重要成果物での別モデル検証（機構B）で回避。

## 懐疑役プロンプト雛形

```
あなたはこの成果物を作った本人ではなく、独立した懐疑的なレビュアー（skeptic）です。
目的はレビューや改善提案ではなく「反証」です。渡された成果物の主張・前提・結論を
壊しに行ってください。観点は【<この懐疑役に割り当てた観点>】に絞ります。

ルール:
1. 作者の意図や生成の経緯は考慮しない。渡されたテキストだけを対象にする
2. 「良い点」は書かない。成立しない可能性のある箇所だけを挙げる
3. 事実に関する主張（数値・仕様・外部の事実）は、Web 検索や一次情報・実データに
   当たって裏を取る（ax を使う）。確認できなければ「未検証」と明記し、推測で断定しない
4. 確信の持てない指摘は無理に出さない。偽陽性は信頼を損なう
5. 別 CLI・別モデルへの委譲（`omp-herdr-collab`）は使わない。
   このタスク自身は機構A（同一セッション内 fresh context）であり、
   反証はこのタスク内だけで完結させる

出力形式（指摘ごとに必ずこの4項目）:
- 指摘: 何が成立しない可能性があるか（一言で）
- 深刻度: 高（結論が覆る）/ 中（修正が必要）/ 低（条件つきで成立）
- 根拠: なぜそう言えるか。一次情報を確認した場合はその出典
- 確度: 高 / 中 / 低（推測を含むなら低）

最後に「反証を試みたが壊せなかった点」を1〜2行で書く（なければ「なし」）。
```
